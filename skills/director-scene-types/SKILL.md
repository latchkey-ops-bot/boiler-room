# Scene types

`scene.type` is one of these 15 ids. This table is the single source of every limit the Director
needs. Build specs are in `docs/motion/scenes/<id>.md`, which repeat these limits for the
engineers who build the scenes.

- **`text` limits** are the exact `SceneLimits.text` object that `sceneRegistry` in
  `packages/schema` gives `validateCampaign`: characters per role. A role a scene type does not
  list falls back to the validator's default limit (headline 60, subhead 120, body 240, cta 30,
  label 40), so write only the roles listed here.
- **Director limits** are yours to keep. The validator does not check words, lines, slot counts or
  layout.
- Every number in any slot needs a cited claim.

## Kinds and rhythm

Kinds feed the rhythm rule [D]: type and proof alternate, a run of one scene type sharing a
headline slot counts as one unit (up to 5 scenes), and a mark resets the count. The templates
follow it everywhere except the closing `colour-event`, callback and name rows, three type units
in a row, which the reference spec leaves as an open decision for the founder. Do not reorder rows
to "improve" rhythm.

## Asset tiers

Use the highest tier the site gives. The Art Director has the full rules.

| Tier | Source                                                                               | Honest status                             |
| ---- | ------------------------------------------------------------------------------------ | ----------------------------------------- |
| 1    | Product screenshots, images or demo video already on the site                        | Real                                      |
| 2    | Docs, changelog, code samples, pricing, integrations pages                           | Real                                      |
| 3    | The marketing site itself                                                            | Real, but shows the site, not the product |
| 4    | Abstract components from verified claims: chips, status lines, rails, greeked panels | Illustrative. Greeked, no numerals        |
| 5    | Generated: backgrounds, texture, illustrative objects                                | Illustrative. `provenance: "generated"`   |

Tier 4 scenes (`status-relay`, `rail-words`, greeked `feature-card`) must be visible to the
customer at script approval: list every one by scene id in your handoff. Never a fake dashboard,
fake data rows, a fake customer name, a fake testimonial, or a logo wall of companies not on the
customer's own site.

## Props

Props are template parameters, never copy. Strings are short ids such as `"name"` or `"mask"`,
and no string in props states a number. Numeric parameters are JSON numbers and are never
displayed: capture data (DOM boxes), word indices and counts. `props.accent` is
`{textId, from, to}`: word indices into one text item, end exclusive, so a scene holds at most one
accent phrase. Text ids contain no digits, because the validator reads a digit in
`props.accent.textId` as a number in props.
